Scope. SAP-specific detection use cases for a SIEM: SAP NetWeaver ABAP (ECC, S/4HANA), SAP HANA, SAP BTP and Cloud Identity Services, the integration and infrastructure tier (gateway, SAProuter, message server, ICM/Web Dispatcher, PI/PO, Cloud Integration), and business-process controls (segregation of duties, payment and master-data fraud). Technique references are MITRE ATT&CK Enterprise IDs, mapped by hand.

Sample logs are representative, not verbatim. They are synthetic, written in the shape the event takes once a SIEM has collected it, and no real system, user, IP, bank account or company appears in them. Actual field names, delimiters and message text vary by SAP release, kernel patch level, audit configuration and connector — a Security Audit Log record read through RSAU_READ_LOG, exported from SM20, pulled over XAL/RFC, forwarded by SAP Enterprise Threat Detection or shipped by a log agent will each look different. Treat these as a normalisation and parser-development reference, and validate every pattern against your own systems before promoting it to an alert.

Prerequisites matter more than the rules. Most of this library is unreachable unless the Security Audit Log is configured and active (RSAU_CONFIG, formerly SM19), table change logging is on (rec/client plus per-table logging), Read Access Logging is configured for the fields you care about, HANA audit policies exist, and BTP/IAS audit log retrieval is wired up. Thresholds shown in the detection logic are starting points to be baselined per landscape, not tuned values.
